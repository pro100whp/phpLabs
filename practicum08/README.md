Практична робота 8. Безпека застосунків (Аудит та усунення вразливостей).
Варіант 15.

Проведено повний аудит коду системи бронювання. Виявлено та виправлено наступні вразливості:

1. SQL-ін'єкція
- Ціль: параметр фільтра за місцем проведення (venue).
- Payload для перевірки: `Arenal' OR '1'='1`
- Усунення: Відмова від конкатенації рядків. Використано підготовлені запити PDO (`prepare` та `execute` з параметром `:venue`).

2. XSS (Міжсайтовий скриптинг)
- Ціль: поле title події.
- Payload для перевірки: `<script>alert('XSS')</script>` при додаванні нової події.
- Усунення: На стороні клієнта у JavaScript додано функцію `escapeHtml()`, яка замінює спецсимволи HTML перед вставкою даних у DOM (innerHTML).

3. CSRF (Підробка міжсайтового запиту)
- Ціль: форма купівлі квитка (зміна seats_left).
- Payload для перевірки: відправка POST-запиту на `/api.php?resource=events&action=buy` зі стороннього сайту без відома користувача.
- Усунення: Додано генерацію `csrf_token` у сесії (`bin2hex(random_bytes(32))`). Токен передається клієнту і перевіряється на бекенді функцією `hash_equals()` при кожному POST-запиті.

4. Незахищена дія та обробка помилок
- Ціль: зменшення seats_left повторним переходом за GET-посиланням.
- Усунення: Маршрутизація API суворо відхиляє спроби змінити дані через GET-запити. Купівля квитка працює виключно через POST із перевіркою CSRF-токена. 
- Також налаштовано перехоплення PDOException: реальні тексти помилок СУБД пишуться у серверний лог (`error_log`), а клієнту повертається загальне повідомлення у форматі JSON.
